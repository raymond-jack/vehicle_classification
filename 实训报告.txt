1. 项目背景分析
--------------------------------------------------------------------------------
随着智能交通系统（ITS）的快速发展以及自动驾驶、智慧停车场、交通监控等
场景的不断落地，车辆类型的自动识别已成为计算机视觉领域的重要研究方向。
传统的车辆识别方法多依赖人工设计的特征（如 HOG、SIFT）结合 SVM 等分类
器，在复杂光照、遮挡、视角变化等场景下鲁棒性较差。

近年来，深度学习尤其是卷积神经网络（CNN）在图像分类任务上取得了突破性
进展。本项目以"车辆图像分类识别"为核心，构建了一个端到端的车辆类型识
别系统，能够对输入的车辆图像自动判别其所属类别，并提供基于 PyQt5 的桌
面客户端与基于 Gradio 的网页端两种交互方式，同时支持摄像头实时识别。

本项目的研究意义在于：
  (1) 实践深度学习图像分类的完整流程：数据采集与分析 → 数据预处理 →
      模型设计与训练 → 模型评估与部署；
  (2) 对比自研 CNN 与迁移学习（EfficientNetB0 / MobileNetV2）两种方案，
      在保证离线可用的前提下选择自研 CNN 作为默认骨干；
  (3) 提供可落地的可视化界面，便于非技术用户直接使用。

本项目涵盖 10 类常见车辆：SUV、公交车（bus）、家用轿车（family sedan）、
消防车（fire engine）、重型卡车（heavy truck）、吉普车（jeep）、
面包车（minibus）、赛车（racing car）、出租车（taxi）、卡车（truck）。

2. 数据集预处理
--------------------------------------------------------------------------------
预处理逻辑集中在 02_data_preprocessing.py，主要包含以下步骤：

2.1 图像解码与缩放
    使用 tf.io.read_file 读取图片文件，tf.image.decode_image 解码为 RGB
    三通道张量，再通过 tf.image.resize 将所有图片统一缩放至
    IMG_SIZE × IMG_SIZE（192×192）。统一尺寸是批处理训练的前提。

2.2 像素归一化
    使用 tf.keras.layers.Rescaling(1.0/255.0) 将像素值从 [0, 255] 归一化
    到 [0, 1] 区间。训练集、验证集、测试集共用同一条归一化管线，确保输入
    分布一致，避免因分布差异导致验证集准确率异常。

2.3 数据增强（仅训练集）
    为提升模型泛化能力、抑制过拟合，对训练集施加数据增强，验证集与测试集
    不做增强：
      - 几何增强：随机水平翻转（tf.image.random_flip_left_right）。
        车辆左右对称，水平翻转不会破坏语义。
      - 光度增强：
          * 随机亮度   random_brightness(max_delta=0.12)
          * 随机对比度 random_contrast(lower=0.85, upper=1.15)
          * 随机饱和度 random_saturation(lower=0.85, upper=1.15)
          * 随机色相   random_hue(max_delta=0.05)
      - 最后使用 tf.clip_by_value 将像素裁剪回 [0, 1]。

    设计说明：未采用 90°/270° 大幅旋转，因为车辆拍摄视角基本固定，整 90°
    翻转会把车变成竖条、破坏语义，反而损害学习。光度扰动幅度也控制在较小
    范围，避免改变车辆的真实颜色特征。

2.4 性能优化
    所有 map 操作使用 num_parallel_calls=tf.data.AUTOTUNE 并行处理，并在
    数据集末尾调用 prefetch(AUTOTUNE) 预取数据，使数据加载与模型训练并行
    执行，提高 GPU 利用率。


3. 数据集划分
--------------------------------------------------------------------------------
采用固定随机种子（SEED=42）的确定性划分，保证实验可复现。划分比例为
训练集 : 验证集 : 测试集 = 70% : 15% : 15%。

具体划分逻辑（02_data_preprocessing.py 中 load_raw_dataset 函数）：
  (1) 扫描 data/ 目录得到所有 (文件路径, 类别索引) 对；
  (2) 使用 np.random.RandomState(SEED).permutation 对索引做确定性混洗；
  (3) 按比例切分：
        n_test      = int(n * 0.15)
        n_val       = int((n - n_test) * 0.15 / (0.70 + 0.15))
        test  = 前 n_test 个
        val   = 接下来 n_val 个
        train = 剩余部分

划分后各集合样本量（总计 3000 张）：
    训练集  train : 约 2100 张（70%）
    验证集  val   : 约 450  张（15%）
    测试集  test  : 约 450  张（15%）

类别名称按字母序排列并保存至 utils/class_names.json，与模型输出索引严格
一一对应，确保推理时标签映射正确。

三、模型设计
================================================================================

1. 模型结构设计
--------------------------------------------------------------------------------
项目在 03_model_build.py 中提供了两类模型方案，通过 utils/config.py 中
的 BACKBONE 参数切换：

  (1) CustomCNN     ：自研 CNN，从零训练，无需联网下载权重（默认）
  (2) EfficientNetB0：ImageNet 预训练迁移学习（需联网）
  (3) MobileNetV2  ：ImageNet 预训练迁移学习，更轻量（需联网）

本项目默认使用 CustomCNN 方案，以保证在无外网环境下也能完整复现训练流程。

1.1 自研 CNN（CustomCNN）结构
    模型由 5 个卷积块 + 全局平均池化 + 双层分类头组成：

    输入层：Input(shape=(192, 192, 3))
    卷积块 1：Conv2D(32, 3×3, same, he_normal) → ReLU → MaxPool2D(2×2)
    卷积块 2：Conv2D(64, 3×3, same, he_normal) → ReLU → MaxPool2D(2×2)
    卷积块 3：Conv2D(128, 3×3, same, he_normal) → ReLU → MaxPool2D(2×2)
              → Dropout(0.25)
    卷积块 4：Conv2D(256, 3×3, same, he_normal) → ReLU → MaxPool2D(2×2)
              → Dropout(0.25)
    卷积块 5：Conv2D(512, 3×3, same, he_normal) → ReLU → MaxPool2D(2×2)
              → Dropout(0.25)

    全局平均池化：GlobalAveragePooling2D
    全连接层 1  ：Dense(256, relu, he_normal)
    Dropout     ：Dropout(0.5)       （DROPOUT_RATE）
    输出层      ：Dense(10, softmax)

    通道数递进：32 → 64 → 128 → 256 → 512，逐步提取从低级纹理到高级语义
    的特征。使用 He 正态初始化（he_normal）以适配 ReLU 激活，缓解梯度消失。

1.2 设计考量
    (1) 不使用 BatchNormalization / LayerNormalization：在当前 TF 2.15 +
        keras3 混合环境下，归一化层存在 train/eval 行为不一致的问题，
        因此采用纯 Conv+ReLU+MaxPool+Dropout 结构，配合强数据增强与
        He 初始化，保证训练与推理一致。
    (2) 全局平均池化（GAP）替代 Flatten：大幅减少参数量，降低过拟合风险。
    (3) 高通道层后加入 Dropout(0.25)，分类头使用 Dropout(0.5)，双重抑制
        过拟合。
    (4) 输出层使用 softmax，输出 10 个类别的概率分布。

1.3 迁移学习方案（可选）
    若选择 EfficientNetB0 或 MobileNetV2，则加载 ImageNet 预训练权重作为
    骨干，冻结骨干后训练自定义分类头（GAP → Dense(256) → Dropout →
    Dense(256) → Dropout → Dense(10, softmax)），再解冻末尾 30 层进行
    低学习率微调。输入需从 [0,1] 映射到 ImageNet 的 [-1,1] 区间。


2. 模型搭建
--------------------------------------------------------------------------------
模型搭建由 03_model_build.py 中的 build_model() 统一入口完成：

    def build_model(num_classes=NUM_CLASSES, **kwargs):
        if BACKBONE == "CustomCNN":
            return build_custom_cnn(num_classes=num_classes)
        return build_transfer_model(num_classes=num_classes,
                                    backbone=BACKBONE, **kwargs)

编译由 compile_model() 完成：
    优化器：Adam(learning_rate=1e-3)
    损失函数：sparse_categorical_crossentropy（标签为整数索引，无需 one-hot）
    评估指标：accuracy

由于标签是整数（0~9），使用 sparse_categorical_crossentropy 可省去
one-hot 编码步骤，简化数据流。


3. 模型训练
--------------------------------------------------------------------------------
训练入口为 04_train.py，核心流程如下：

3.1 训练策略（CustomCNN）
    - 从零训练，总轮数 = HEAD_EPOCHS + FINETUNE_EPOCHS = 15 + 12 = 27 轮
      （实际由 EarlyStopping 提前终止，最终训练 17 轮）
    - 初始学习率 HEAD_LEARNING_RATE = 1e-3

3.2 回调函数（make_callbacks）
    训练过程中使用三个 Keras 回调：
      (1) ModelCheckpoint
          - monitor="val_accuracy"，mode="max"
          - save_best_only=True，仅保存验证准确率最高的模型权重
          - 保存路径：models/vehicle_cnn.h5
      (2) EarlyStopping
          - monitor="val_accuracy"，patience=10
          - restore_best_weights=True，恢复最佳权重
          - 连续 10 轮验证准确率无提升则停止训练
      (3) ReduceLROnPlateau
          - monitor="val_loss"，factor=0.5，patience=3
          - min_lr=1e-7
          - 验证损失 3 轮不下降则学习率减半，帮助模型跳出局部最优

3.3 训练过程记录
    训练历史保存在 results/history.json，包含 accuracy、loss、
    val_accuracy、val_loss、learning_rate 五个指标的逐轮数值。
    实际训练 17 轮后由 EarlyStopping 终止。

3.4 独立测试集评估
    训练完成后，在独立的 15% 测试集上评估：
        Test Loss:     0.4565
        Test Accuracy: 0.8756  （87.56%）
    结果同时写入 results/train_summary.json。


4. 模型保存
--------------------------------------------------------------------------------
模型以 HDF5 格式保存至：models/vehicle_cnn.h5
    - 由 ModelCheckpoint 在训练过程中自动保存验证准确率最高的权重；
    - EarlyStopping 的 restore_best_weights=True 确保最终内存中的模型
      即为最佳权重；
    - 推理时通过 tf.keras.models.load_model(MODEL_PATH) 直接加载。

类别映射保存至：utils/class_names.json
    - 内容为 10 个类别名称的字母序列表，索引与模型输出神经元一一对应；
    - 推理时 VehiclePredictor 加载该文件将预测索引转换为类别名称。

1. 模型性能评估指标可视化（准确率、损失率等）
--------------------------------------------------------------------------------
训练过程的准确率与损失曲线由 05_evaluate.py 中的 plot_history() 函数
根据 results/history.json 绘制。

1.1 准确率曲线
    【图 4】训练集与验证集准确率曲线
        图片位置：results/accuracy.png

    曲线分析：
      - 训练准确率（train accuracy）从第 1 轮的 0.24 稳步上升至第 17 轮的
        约 0.62，整体呈单调上升趋势，说明模型在持续学习；
      - 验证准确率（val accuracy）在前 5 轮较低（0.08~0.14），第 6 轮起
        快速上升，第 8 轮达到约 0.52 的峰值，随后在 0.41~0.50 区间波动；
      - 训练准确率与验证准确率存在一定差距，表明模型存在轻度过拟合，
        但通过 Dropout 与数据增强已得到有效控制；
      - ReduceLROnPlateau 在训练过程中多次下调学习率（1e-3 → 5e-4 →
        2.5e-4 → 1.25e-4 → 6.25e-5），有助于模型后期稳定收敛。

1.2 损失率曲线
    【图 5】训练集与验证集损失曲线
        图片位置：results/loss.png

    曲线分析：
      - 训练损失（train loss）从 2.12 持续下降至 1.13，呈稳定下降趋势；
      - 验证损失（val loss）在前几轮出现波动上升（最高约 5.04），第 6 轮
        起快速下降，第 8 轮降至约 1.43，随后在 1.43~1.79 区间波动；
      - 验证损失的早期波动与验证准确率的初期低迷相对应，反映模型在训练
        初期尚未学到有效特征；
      - 整体来看损失曲线趋势合理，模型最终在测试集上取得 0.4565 的损失。

1.3 学习率变化
    由 history.json 中 learning_rate 字段可知，学习率随训练推进逐步衰减：
        第 1~4 轮：1.0e-3
        第 5~7 轮：5.0e-4
        第 8~12 轮：2.5e-4
        第 13~15 轮：1.25e-4
        第 16~17 轮：6.25e-5
    该自动衰减机制由 ReduceLROnPlateau 触发，有效避免了后期学习率过大
    导致的震荡。

================================================================================
五、系统可视化界面
================================================================================

为便于模型的实际使用与演示，本项目提供了两套可视化交互界面：基于 PyQt5
的桌面客户端（main.py / app/gui.py）与基于 Gradio 的网页端
（Gradio_main.py）。两套界面共享同一套推理核心
（app/vehicle_predictor.py），均支持图片识别与摄像头实时识别。

1. 推理核心封装（VehiclePredictor）
--------------------------------------------------------------------------------
两个界面都依赖 app/vehicle_predictor.py 中的 VehiclePredictor 类，
该类将模型加载、图像预处理、预测推理封装为统一接口：

  - __init__：加载 models/vehicle_cnn.h5 模型与 utils/class_names.json
    类别映射；
  - preprocess：BGR→RGB → resize(192×192) → /255.0 → 扩维，与训练
    预处理严格一致；
  - predict(image_path)：按路径预测单张图片，返回 (label, confidence)；
  - predict_frame(frame)：对摄像头帧（BGR 数组）预测；
  - predict_topk(frame, k=3)：返回 Top-K 类别与置信度列表（降序）。

摄像头操作由 app/camera.py 中的 Camera 类统一管理，支持打开、读取帧、
释放、切换摄像头等操作。


2. PyQt5 桌面端界面（main.py / app/gui.py）
--------------------------------------------------------------------------------
启动命令：python main.py
窗口标题："车辆图像分类识别系统"，初始尺寸 900×700。

界面组成（由 app/gui.py 的 VehicleGUI 类构建）：

  (1) 图像显示区
      - 640×420 的 QLabel，居中显示，带灰色边框；
      - 支持显示本地图片或摄像头实时画面。

  (2) 结果显示区
      - QLabel 显示预测类别与置信度（百分比格式），字体 20px。

  (3) 图片识别功能区
      - "选择图片"按钮：调用 QFileDialog 选择 *.jpg/*.png/*.jpeg 图片，
        按比例缩放后显示在图像区；
      - "图片识别"按钮：调用 predictor.predict 对所选图片推理，结果
        显示在结果区。

  (4) 摄像头实时识别功能区
      - 下拉框选择"摄像头 0 / 摄像头 1"；
      - "打开摄像头"按钮：创建 Camera 对象，启动 QTimer（30ms 间隔）

      - "关闭摄像头"按钮：停止定时器、释放摄像头资源；
      - 每采集 15 帧（predict_interval=15）调用一次 predict_camera
        进行实时推理，平衡识别流畅度与性能开销；
      - 窗口关闭时（closeEvent）自动释放摄像头，避免资源泄漏。

六、结论及建议
================================================================================

1. 模型优点与先进性
--------------------------------------------------------------------------------
(1) 完整的工程化流程
    项目覆盖了从数据采集分析、预处理、模型设计、训练、评估到部署的完整
    深度学习工程链路，代码结构清晰、模块职责分明（按 01~06 编号组织），
    具有良好的可维护性与可复现性。

(2) 离线可用的自研 CNN
    默认骨干 CustomCNN 无需联网下载预训练权重，在无外网环境下即可完整
    训练与部署，适合教学与实训场景。5 层卷积块通道数递进设计（32→64→
    128→256→512）符合经典 CNN 特征提取规律。

(3) 充分的正则化手段
    综合运用 He 初始化、Dropout（高通道层 0.25 + 分类头 0.5）、数据增强
    （水平翻转 + 光度扰动）、全局平均池化等技术，在不依赖 BatchNorm 的
    前提下有效控制过拟合，保证 train/eval 行为一致。

(4) 智能训练策略
    采用 ModelCheckpoint（保存最佳权重）、EarlyStopping（自动早停）、
    ReduceLROnPlateau（自适应学习率衰减）三大回调，训练过程无需人工
    干预，且最终模型为验证集表现最优版本。

(5) 灵活的模型切换与多端部署
    通过 BACKBONE 配置可在 CustomCNN / EfficientNetB0 / MobileNetV2 间
    切换；同时提供 PyQt5 桌面端（main.py）与 Gradio 网页端
    （Gradio_main.py）两种交互方式，并支持摄像头实时识别，应用场景广。

(6) 较好的识别效果
    在 10 类车辆、每类 300 张的数据集上，测试准确率达到 87.56%，混淆
    矩阵显示 SUV、bus、fire engine、truck 等类别识别率达 100%，整体
    表现良好。


2. 模型可改进之处
--------------------------------------------------------------------------------
(1) 引入归一化层与更先进的骨干
    当前环境限制下未使用 BatchNormalization。在标准 TensorFlow 环境中
    加入 BatchNorm 可显著加速收敛并提升准确率；也可启用 EfficientNetB0
    等预训练骨干进行迁移学习，预期准确率可提升至 95% 以上。

(2) 增加数据多样性与数量
    每类仅 300 张样本相对较少，可进一步扩充数据集，或引入 Mixup、
    CutMix、随机裁剪、随机擦除（Random Erasing）等更丰富的数据增强
    策略，提升模型对遮挡、复杂背景的鲁棒性。

(3) 优化类别间相似样本的区分
    混淆矩阵显示 heavy truck 与 truck、family sedan 与 taxi 等外观
    相似类别易混淆，可考虑：使用更大的输入分辨率（如 224×224）、增加
    细粒度特征提取模块、或引入类别间的对比损失（Contrastive Loss）。

(4) 更精细的超参数调优
    可使用贝叶斯优化或网格搜索对学习率、Dropout 率、卷积通道数等超参数
    进行系统调优；也可尝试余弦退火学习率调度（Cosine Annealing）替代
    ReduceLROnPlateau。

(5) 统一评估数据划分
    当前 04_train.py 与 05_evaluate.py 使用了不同的测试集划分方式
    （自定义 70/15/15 vs image_dataset_from_directory 的 80/20），
    建议统一为同一种划分逻辑，保证训练与评估指标的一致性与可比性。

(6) 模型轻量化与部署优化
    可对训练好的模型进行量化（Quantization）、剪枝（Pruning）或导出为
    TensorFlow Lite / ONNX 格式，降低推理延迟，便于在边缘设备
    （如嵌入式摄像头、手机端）部署。

(7) 增加更多评估指标
    除准确率与损失外，可补充精确率（Precision）、召回率（Recall）、
    F1-Score、ROC 曲线等指标，更全面地衡量模型在各类别上的表现，尤其
    是在类别不平衡场景下。
